# Architecture

## Overview

```
Browser ──► Next.js 16 (App Router, TypeScript, Tailwind 4) on Vercel
              │
              ├─ Pages: /, /ask, /constitution, /constitution/[id], /topics, /topics/[slug], /about
              │     read data/constitution.en.json (bundled, generated by scripts/ingest.mjs)
              │
              ├─ GET  /api/search   lexical search (MiniSearch BM25, in process)
              └─ POST /api/ask      retrieve ─► plan (small model) ─► retrieve ─► answer (large model)
                                    ─► validate citations ─► JSON
                                          │
                                          └─► Anthropic API (server-side key only)
```

There is no runtime database. The constitutional text is a build artefact, so the reader and search keep working if every external service is down.

## Ingestion (`scripts/ingest.mjs`)

1. Loads the active source from `data/sources/manifest.json` and checks its SHA-256.
2. Parses chapters, parts, articles and schedules, keeping the original clause markers ((1), (a), (i)).
3. Runs integrity checks: unique ids, no empty provisions, articles in order, no gaps from 1 to the last article, and the `expected` counts from the manifest.
4. Writes `data/constitution.en.json` only if every check passes. `--check` mode fails if the committed file differs from a fresh parse (used in CI).

The only transformation of the text is collapsing whitespace. Nothing is generated or corrected.

## Search (`lib/search.ts`)

- One document per provision (articles, preamble, schedule sections). Repealed provisions are excluded.
- BM25 over text, editorial label and citation label, with a light stemmer, prefix and fuzzy matching.
- Query expansion: a hand-written map from everyday words to constitutional vocabulary ("lawyer" → "legal practitioner"), and a small French/Kreol keyword map. Expansion only widens retrieval.
- "Article 22" style queries return that provision first.

## Constitution AI (`lib/ai.ts`)

1. **Plan** – a small model returns the question's language, whether it concerns the Constitution, up to four English search queries and any article numbers the user named.
2. **Retrieve** – reciprocal-rank fusion of the original question and planned queries; named articles first; at most 8 provisions, sent in full.
3. **Answer** – the main model receives only those provisions and returns structured JSON (`status`, `short_answer`, `provisions[]`, `what_this_means`, `limitations[]`).
4. **Validate (in code)** – citations whose id was not retrieved are removed; an "answered" result with no surviving citation becomes "not found"; article numbers mentioned in prose but never shown to the model are reported to the user.
5. **Fallback** – no key, API error, refusal, unparsable output or daily cap ⇒ the matching provisions are shown without an explanation, with a notice saying why.

Prompt-injection posture: the question and provisions are passed inside tags and the system prompt treats them as data; the model has no tools and no secrets; output is structured, validated, and rendered as plain text by React (no HTML or Markdown rendering).

Not implemented: the Anthropic server-side refusal-fallback parameter. A refusal simply falls back to retrieval-only.

## Voice (`components/useSpeech.ts`)

Browser Web Speech API. Microphone → recogniser → text appended to the question box → user edits → user presses Ask. Nothing is submitted automatically. Handles: unsupported browser, permission denied, no speech, other errors; releases the microphone on unmount. Audio never reaches this application.

## Read aloud (`components/ReadAloud.tsx`, `lib/tts.ts`)

Browser `speechSynthesis`. Text is cleaned for speech (placeholder dots removed, "/" read as "or") and split into pieces of at most about 220 characters, because Chrome cuts off long single utterances. Pieces are queued one at a time. Pause is implemented as stop-and-remember-position, which behaves the same everywhere (native pause is unreliable on Android). Only one reader plays at a time, and speech stops when the reader leaves the page. Articles are read in English; AI answers in the answer's language, with French voices standing in for Kreol Seselwa. The control is hidden in browsers without speech synthesis.

## Internationalisation (`lib/i18n/`)

Typed dictionaries (`en`, `fr`, `crs`) selected by a cookie. `localeMeta[locale].reviewed` controls the "unreviewed translation" banner. Constitutional text is always rendered with `lang="en"`.

## Security

| Concern | Measure |
| --- | --- |
| API key | Server-side environment variable only; never sent to the browser. |
| Input | Zod validation, 500-character limit, content-type and body-size checks. |
| Abuse and cost | Per-IP limits (6/min, 60/day on `/api/ask`; 60/min on search) and a per-instance daily cap on paid AI calls. All configurable. |
| Output | React escaping; no `dangerouslySetInnerHTML` on user or AI content. |
| Headers | CSP (self only, no framing), `nosniff`, `X-Frame-Options: DENY`, HSTS, restrictive Permissions-Policy (microphone for this origin only). |
| Logging | Errors log the error class only, never the question. Questions travel in the URL fragment and POST body, not in query strings. |
| Database | Row-level security on every table; public role is read-only on published versions, insert-only on feedback. |

Known gaps: the rate limiter is in memory, so on serverless hosting each warm instance counts separately (add a shared store or the host's firewall rules before heavy traffic). The CSP allows inline scripts because Next.js requires them without a nonce setup.

## Database (optional)

`supabase/migrations/20261116000000_init.sql` defines `source_documents`, `document_versions`, `amendments`, `chapters`, `parts`, `provisions` (with a generated `tsvector` and GIN index), `editorial_labels` and `feedback`, plus `search_provisions()` and `publish_version()`. It was applied and exercised on a local PostgreSQL 16 server. It has not been applied to a Supabase project, and the running site does not read from it. Use it when you need feedback collection, multiple published versions, or a public data API. `supabase/optional/pgvector.sql` is an untested sketch for semantic search.
